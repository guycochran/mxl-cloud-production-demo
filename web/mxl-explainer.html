EBU MXL · Architecture note

The tenth consumer of a camera is a pointer, not a stream.

Why zero-copy shared memory changes the economics of a software production plant — and where the "free" honestly stops.

MXL collapses the interior of the plant to zero-copy, zero-codec. Encode and decode happen only at the true edges — camera in, stream out — never in the middle.

01 What a "pull" actually costs

An MXL flow is a ring buffer of grains living in /dev/shm — tmpfs, which is RAM. The producer writes each frame once. A consumer mmap()s the same physical pages and reads through a head pointer. So the marginal cost of the Nth reader is:

≈ Free

Pixel copies

Zero. Every reader maps the same physical RAM. No fan-out duplication of the video itself.

≈ Free

Codec cycles

Zero. The v210 grains sit uncompressed; each reader reads them natively. No decode, no re-encode.

≈ Free

Added latency

~None. A reader sees the frame the instant it's published — no encode / packetize / depacketize pipeline.

Paid per user

Memory bandwidth

Real, but only when a reader touches pixels (composite, scale). ~166 MB/s per 1080p30 v210 read. This — not codecs — is the ceiling.

02 Codec-only-at-edges

Ten switchers pulling the same cameras — each rendering different-language graphics and its own program output. The camera is ingested once; the ten readers share its pixels. Only each switcher's own egress encode scales.

// interior = pointer reads · codec cost lives only at ingress + egress

03 Against SDI · ST 2110 · NDI

Each existing option gives you two of the three things you want. MXL is the one that delivers uncompressed and software fan-out — bounded by RAM bandwidth, not codecs.

TransportInterior mediumPer-consumer copyCodec cyclesLatency / hopScope
SDI Coax, point-to-point hardware none ~0 One cable = one signal
ST 2110 IP multicast, uncompressed network none sub-frame + NIC/PTP Whole facility
NDI IP, compressed bw × N decode × N several ms (codec+net) LAN, flexible
MXL Shared memory (RAM) none · mmap none interior ~0 (memory read) Single host / NUMA

The compounding win: a signal that travels camera → switcher → graphics → multiviewer → record can eat 4–5 encode/decode round-trips in an NDI plant — generational loss and accumulating latency at every stage. In MXL that same path is 4–5 pointer reads. And because it's an open EBU spec — not a proprietary codec or a hardware-anchored standard — any process that can mmap is a producer or consumer, in any language. That is literally the ten-switchers-in-different-languages case.

◈ Where the "free" stops

The zero-copy magic is bounded by one shared-memory domain — a single host / NUMA node. The moment a flow must reach another machine, you're back to a transport that costs network I/O.

Uncompressed is not cheap on the wire: a single 1080p30 v210 flow is ~1.2 Gbps; 4K or high frame rates balloon fast. So the real cloud-plant trade is: keep co-located consumers on one big host to exploit zero-copy, and pay network only at genuine host boundaries. (It's exactly why the lab's primary node is a 32-core VM rather than a scatter of small ones.)

MXL composes with 2110 — it doesn't replace it. MXL is the intra-host exchange layer; 2110 remains the inter-host / facility transport.
