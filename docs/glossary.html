MXL concepts, defined

The vocabulary of shared-memory, software-defined production — in plain English, with a note on why each one matters. If a term on this site is unfamiliar, it's here.

Grain
A single timestamped unit of media — one video frame, or a block of audio samples. The atomic thing MXL moves around. Because every grain carries a TAI timestamp, position in a stream is a time, not a queue slot.
Flow
A continuous sequence of grains of one media type (e.g. a camera's 1080p30 video). In MXL a flow is a small ring buffer in shared memory — often just a handful of grains deep — indexed by TAI time. Producers write into it; any number of consumers read from it.
MXL Domain
The shared-memory region (on a host, typically under /dev/shm/mxl) where flows live. A media function joins the domain and can immediately discover and read every flow in it — no cabling, no re-routing. The domain is the router.
Media function
A small, single-purpose program that reads and/or writes flows: a selector, a keyer, an audio mixer, a multiviewer compositor. A "switcher" is just a connected set of these functions — not a box.
Zero-copy
Reading media straight out of shared memory without copying the bytes. The consequence that matters: the tenth consumer of a camera is a pointer, not another stream. Fan-out is nearly free, unlike NDI/SDI/ST-2110 where each consumer is another copy on the wire.
Fabrics API
MXL's mechanism for extending a domain across hosts. Grains written on one machine appear in another machine's shared memory over the network (built on libfabric). In our tests: 1.3 Gbps of live 1080p30 with the receiving host's CPU ~idle, because remote writes land directly in the destination ring. See the numbers →
v210
A 10-bit uncompressed YUV 4:2:2 pixel format — the "mezzanine" quality carried inside the domain so functions never compound compression artifacts. Encoding happens once, at the edge, for delivery.
TAMS Time-Addressable Media Store
A store where media is addressed by timerange rather than by file. A clip is just a new reference to an existing timerange — zero bytes copied. Pairs naturally with MXL's TAI-indexed grains: record the live program and clip from it while the show is still going. The full recipe →
NMOS AMWA IS-04 / IS-05 …
The AMWA family of specs for discovering, connecting and controlling networked media. BCP-007-03 defines how MXL flows appear to standard NMOS controllers — the path from "a demo" to "a facility a broadcast controller can operate."
DMF Dynamic Media Facility
The EBU's reference architecture for a software-defined broadcast facility built from composable media functions. MXL is its data plane; TAMS its store; NMOS its control plane. Where to start →
Reader-lifecycle wedge
A family of failure modes where a flow reader silently stops delivering fresh content — while rate and head-freshness metrics still read green. The single most important operational lesson from running MXL live; it has (at least) five distinct species. The taxonomy →
